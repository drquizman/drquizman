# 3D-ведущий в Android TV

Интеграция: 21 сентября 2026. Постановка из `preview/director/direction.md` перенесена в существующие игровые экраны. `GameEngine`, правила, тексты, счёт и длительность фаз не изменены.

## Ассет и воспроизведение

- Исходник: `assets/host-3d-v1/archive-doctor/doctor-animated.glb`, новый скелет v2. Исходный GLB не изменяется.
- `tools/prepare-android-host.cjs` создаёт Android-копию с морфами открывания рта и моргания в `tv/src/main/assets/host`. Gradle запускает подготовку автоматически; нужен Node.js.
- Нативный рендер: Filament / gltfio 1.75.1, прозрачный TextureView, равномерные 30 кадров/с по vsync с накоплением времени; буфер 3D ограничен 1280×720, интерфейс остаётся в разрешении экрана. Все ABI сохранены.
- Один постоянный полноэкранный слой модели живёт вне ветвлений по фазам; игровые компоновки задают только положение ведущего. Поверхность не переносится и не пересоздаётся между сценами. Область рендера занимает весь экран без обрезания по месту ведущего. Весь игровой интерфейс, включая верхнюю панель и карточки игроков, расположен поверх 3D-слоя. До измерения места ведущего первый кадр не рисуется. При уходе с экрана ресурсы освобождаются, при сворачивании рендер останавливается. При ошибке загрузки/графического контекста остаётся резервная картинка.
- Голос и события артикуляции поступают из существующего HostSpeech / Android TTS. Морф рта быстро реагирует на текущую визему; внутри слов TTS используются приблизительные буквенные движения с шагом 70 мс вместо удержания одной позы. Это не фонемная синхронизация. Новые аудиозаписи не добавлены.

## Исполняемая режиссура

`core/.../host/HostDirector.kt` — контроллер постановки; `HostModelView.kt` — камера, скелетное смешивание и лицо.

| Событие | Движение | Камера |
|---|---|---|
| Вход в лобби / новый игрок | hi, затем разговор или wait | Общий |
| Начальное приветствие INTRO без конкурса | Разговор | Крупный |
| Объявление конкурса INTRO | Разговор | Средний |
| TITLE | wait | Общий |
| TOPIC, QUESTION, REVEAL | Разговор во время речи, затем wait | Общий; ответы и игроки видны |
| BET, объявление | Разговор | Средний |
| BET, окно ставок | count | Общий |
| GAME_OVER, речь | Разговор | Средний |
| GAME_OVER, после речи | dance; при явном «хаха» в реплике сначала laughing | Общий |
| Пауза | Замороженная поза и камера | Без движения |

Разговор: talking, talking2, talking3, arguing. Перемешанный набор без повторов подряд, смешивание за 380 мс. Обновления таймера не перезапускают клип. Камера плавно меняет дистанцию. Ведущий остаётся в существующей левой колонке игры (в веб-эскизе другая компоновка).

Отличия от веб-эскиза: TTS не сообщает точную оставшуюся длительность, поэтому правило «не начинать жест за 800 мс до конца» не применяется; после окончания речи выполняется переход в ожидание. Дополнительного удержания победы на пять секунд нет: жизненный цикл экрана определяет игра. Длительные финальные клипы могут прерваться при переходе движка. Веб-звуки и постановочные эффекты не заменяют существующее игровое аудио.

## Проверка

- `:core:checkHostDirector`: набор жестов, стабильность на тиках таймера, пауза, рот, ставки, победа и приветствие.
- `:core:checkLocalization`: существующая проверка локализаций.
- `:tv:assembleDebug`: установочный APK.
- Android TV эмулятор: реальный Filament, все четыре разговорных клипа, переходы INTRO → QUESTION → пауза → REVEAL → BET → GAME_OVER, одна загрузка модели, танец победы. Debug-only `DesignReviewActivity --es screen director` повторяет эту проверочную последовательность.
- Полный `:tv:lintDebug` обнаруживает существующую ошибку `CoarseFineLocation` в AndroidManifest.xml. Новых ошибок Lint в 3D-компонентах нет.
- Производительность на физическом телевизоре и полную сетевую партию с телефонами нужно проверить на устройстве.

## Бэкап и возврат

Бэкап до интеграции: `backups/before-3d-20260921-141921/`.

- `source.zip` — исходники, конфигурация, модели и веб-образец до изменений.
- `DrQuizman-before-3d.apk` — предыдущий установочный APK.
- `SHA256.txt` — контрольные суммы.

Для возврата исходников распаковать source.zip в отдельную пустую папку и открыть её как проект. Не распаковывать поверх новой версии: новые файлы 3D останутся. Для возврата приложения установить старый APK с той же подписью поверх нового; при отказе Android из-за номера версии собрать бэкап с повышенным versionCode, чтобы сохранить данные приложения.

## Расширение постановки — 22 сентября 2026

В Android подключены 24 клипа из обновлённого doctor-animated.glb (скелет v2). Эта таблица уточняет выбор анимаций в игре; веб-эскиз сохраняет прежнюю демонстрационную последовательность. Распределение новых жестов основано на названиях и русских метках из tools/doctor-gesture-clips.cjs.

| Ситуация | Случайный набор |
|---|---|
| Ожидание ответа, тишина между репликами | wait, weight_shift |
| Меню и ожидание в лобби | wait, weight_shift, look_away_gesture, relieved_sigh |
| Чтение вопроса, независимо от настроения | talking, talking2, talking3, arguing — без жестов «да/нет» |
| Обычная речь вне вопроса | talking, talking2, talking3, arguing, acknowledging, head_nod_yes, lengthy_head_nod |
| Радостная речь HAPPY / энергичная HYPE | Обычный разговор + happy_hand_gesture, hard_head_nod |
| HYPE при INTRO или GAME_OVER | Радостный разговор + being_cocky |
| SAD при REVEAL, когда ответ уже показан | talking, talking2, talking3, arguing, shaking_head_no, thoughtful_head_shake, relieved_sigh, annoyed_head_shake |
| Приветствие игрока | hi один раз, затем подходящий разговор или ожидание |
| Открытые ставки | count, приоритет над случайным ожиданием |
| Победа после речи | dance; laughing только при явном смехе в тексте |
| Заставка TITLE | wait; случайные жесты отключены |
| Пауза | Текущая поза заморожена |

Наборы перемешиваются мешком вариантов, без повторения текущего клипа подряд. Следующий вариант начинается за 380 мс до окончания текущего со смешиванием поз. После речи выбирается ожидание, а не остаётся разговорный жест. Тики таймера не перезапускают выбор; фазы, голос, счёт и игровые задержки не меняются. Используются только клипы, реально присутствующие в загруженном GLB.

angry_gesture, dismissing_gesture и sarcastic_head_nod сохранены в ассете как резерв. В текущих событиях нет отдельного достоверного сигнала сердитой, пренебрежительной или саркастической реплики, поэтому они не подмешиваются случайно в нейтральную речь и не направляются на ошибившегося игрока.
